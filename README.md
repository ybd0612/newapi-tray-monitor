# NewAPI 托盘监控小工具

一个面向 Windows 的 NewAPI 用量与余额常驻监控工具。它不追求复杂的后台管理，而是把最常用的几个问题直接放在屏幕边缘：

- **今天用了多少？** 查看今日消费、请求量和 Token。
- **本月用了多少？** 查看本月累计请求量和 Token。
- **还剩多少钱？** 查看当前余额，并在余额低于阈值时醒目标记。
- **现在的数据新不新？** 按配置周期自动刷新，并在刷新失败时保留上一次成功数据。

## 产品定位与设计思想

> **直观、准实时、低打扰、低资源。**

### 1. 直观

打开面板即可看到余额、今日消费、本月请求量、今日请求量、本月 Token 和今日 Token，不需要进入网页后台、翻日志或手动计算。金额统一按配置的额度换算因子展示，当前默认以额度单位 / `500000` 换算。

### 2. 准实时

当前实现采用“启动立即查询 + 按周期轮询”的方式更新数据，而不是长连接推送。默认每 60 秒刷新一次，最小可配置为 10 秒；每次刷新并行获取用户余额、今日统计、今日数据和本月数据。这里的“实时”是面向日常使用的**准实时监控**，实际数据新鲜度取决于刷新间隔和 NewAPI 服务端数据更新速度。

### 3. 低打扰

应用常驻系统托盘，面板使用无边框、透明、置顶且不显示在任务栏的轻量窗口。面板可以拖动到屏幕角落，也可以通过滚轮调整透明度，尽量做到“看得到，但不挡住其他程序”。开机启动时默认驻留托盘，不主动弹出面板。

### 4. 低资源

项目使用 Tauri 2 + 系统 WebView，而不是内置完整浏览器运行时；数据只在刷新时请求，不持续读取日志、不建立高频后台任务、不保存本地历史数据库。指标查询优先使用 `/api/data/self` 的时间范围汇总接口，避免为统计本月数据而逐条翻页读取日志。

## 当前功能

| 关注点 | 当前展示或行为 |
| --- | --- |
| 剩余金额 | 当前余额；低于余额提示阈值时显示红色 |
| 今日用量 | 今日消费金额、今日请求量、今日 Token |
| 本月用量 | 本月请求量、本月 Token |
| 刷新机制 | 启动立即刷新，之后按配置周期轮询；默认 60 秒，最小 10 秒 |
| 时间口径 | 今日按本地时区自然日统计；本月按当月 1 日至当前时刻统计 |
| 异常处理 | 单次失败保留上一次成功数据，连续失败超过 3 次才显示错误提示 |
| 窗口体验 | 无边框、透明、置顶、跳过任务栏；支持拖动、调整大小和透明度 |
| 常驻方式 | 系统托盘菜单支持显示面板、隐藏面板、设置和退出 |
| 启动方式 | 支持 Windows 开机自动启动；开机后默认只驻留托盘 |

## 技术栈

- Tauri 2.x + Rust
- Vite 5 + React 18
- MUI v5 + Tailwind CSS 3
- `@tauri-apps/plugin-http`：请求 NewAPI 接口
- `@tauri-apps/plugin-autostart`：Windows 开机自启
- 配置保存在当前 WebView 的 `localStorage` 中，不引入额外数据库依赖
- Windows 发布使用 Tauri NSIS 打包；当前没有接入自动更新客户端

## 运行步骤

环境要求：Windows、Node.js、Rust 工具链和 Tauri 所需的 Windows 构建环境。

```bash
npm install
npm run tauri:dev       # 启动 Tauri 开发模式，固定使用 Vite 端口 52317
npm run tauri:build     # 构建 Windows 安装包，输出到 src-tauri/target/release/bundle/
```

仅构建前端资源时：

```bash
npm run build           # 生成 dist/，不启动桌面应用
npm run build:tauri     # 生成 Tauri 使用的前端资源，不清理已有 dist/
```

> Vite 开发端口固定为 `52317`，端口被占用时会直接报错，不会自动换端口。修改前端代码后，优先使用 `npm run tauri:dev` 验证桌面窗口行为。

## 使用说明

1. 首次启动后，在“设置”中填写 NewAPI 中转站 URL 和访问令牌；部分部署还需要填写数字用户 ID（`New-Api-User`）。
2. 点击“测试连接”确认接口可用，再点击“保存”。
3. 在主面板查看余额、今日用量和本月用量；面板会按更新频率自动刷新。
4. 可在设置中调整刷新频率和余额提示阈值。余额严格低于阈值时显示红色，等于阈值时不标红。
5. 拖动面板可保存位置；调整窗口大小会保存尺寸；在面板上滚动鼠标滚轮可调整透明度，范围为 35%～100%。
6. 托盘菜单可隐藏面板、重新显示面板、打开设置或退出应用。

## 数据来源与统计口径

- 余额与累计信息来自 `GET /api/user/self`，读取 `quota`、`used_quota` 和 `request_count`。
- 今日消费来自 `GET /api/log/self/stat?start_timestamp&end_timestamp`。
- 今日与本月的请求量、Token 来自 `GET /api/data/self` 的时间范围汇总数据，应用累加返回行中的 `count` 和 `token_used`。
- 查询时间使用本机本地时区生成 Unix 时间戳；“今日”不是滚动 24 小时。
- 当月份跨越 27 天时，本月查询会自动拆分为多个不超过 27 天的时间段后合并，避免单次时间范围过大。
- 所有金额都按 `额度单位 / factor` 换算，当前设置页固定使用 `factor = 500000`，并以 4 位小数展示。

## Windows 发布

项目使用 Tauri CLI 构建 Windows NSIS 安装包：

```bash
npm run tauri:build
```

构建产物位于：

```text
src-tauri/target/release/bundle/nsis/
```

当前项目已发布过 `v1.0.1`，发布记录和安装包信息见 [`overview.md`](./overview.md)。后续发布前需要同步更新 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 中的版本号，并生成新的安装包。

## 依赖与镜像说明

- 项目已写入 `.npmrc`，默认配置 npm registry 为淘宝 npmmirror；`electron_mirror` 是历史配置项，当前 Tauri 构建不依赖 Electron，可按需移除。
- `package.json` 的 `optionalDependencies` 显式固定了 Windows 平台原生二进制 `@rollup/rollup-win32-x64-msvc` 与 `@esbuild/win32-x64`，用于规避 npm 可选依赖缺失导致的构建问题；这两个包仅 Windows 需要，其它平台安装时会被安全跳过。

## 已知限制与后续方向

### 当前限制

- 当前是按周期轮询，不是服务端 WebSocket/SSE 推送；刷新间隔越短，数据越及时，但请求次数和资源消耗也会增加。
- 面板展示的是当前余额和汇总指标，暂未提供按天、按模型、按令牌的历史趋势图。
- NewAPI 不同部署版本返回字段和鉴权要求可能存在差异；若接口要求 `New-Api-User`，需要在设置中填写用户 ID。
- 当前只支持单个中转站、单个访问令牌，不支持多账号切换。
- 透明窗口依赖 Windows 10+ 的桌面能力；个别 Windows 版本托盘图标显示可能存在差异。

### 后续方向

后续功能应继续围绕“看得懂、更新快、不打扰”推进，优先级建议如下：

1. **用量趋势**：增加今日/本月消费趋势和按天汇总，帮助快速判断使用速度。
2. **剩余额度预警**：除余额阈值外，增加连续失败、余额接近耗尽等低打扰提醒。
3. **更轻量的刷新策略**：面板隐藏时降低刷新频率，面板显示时恢复正常频率；失败时采用退避重试，减少无效请求。
4. **信息密度优化**：在不增加窗口面积的前提下，继续优化数字层级、颜色和更新时间展示。
5. **多账号支持**：在确认单账号体验稳定后，再考虑多中转站/多令牌管理。
