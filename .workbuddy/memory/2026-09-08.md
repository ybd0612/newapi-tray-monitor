## 构建产物统一到单一 build/ 目录

背景：项目根目录堆积 10 个构建目录（release + 9 个 release-*，约 1.7GB，其中 4 个是 Electron 时代残留，含 58 个 .pak）。

改动：
- `vite.config.js`：`outDir` 由 `dist` 改为 `build/frontend`；`src-tauri/tauri.conf.json` 的 `frontendDist` 同步为 `../build/frontend`。
- 新增 `scripts/copy-installer.mjs`：`tauri:build` 后自动把 `src-tauri/target/release/bundle/nsis` 下的 `.exe`/`.sig` 复制到 `build/installer/`；`package.json` 的 `tauri:build` 追加 `&& npm run collect`。
- `.gitignore`：用 `build/` 取代 `dist/` 与 `release*/`；新增 `/release-*/` 过渡规则（遗留空目录清理后可移除）。
- 文档同步：`README.md`（运行步骤、构建产物路径、新增 build/ 目录结构说明）、`overview.md`（v1.0.5 构建结果补注收集位置）。
- 已删除：原 `dist/`、两个 `vite.config.js.timestamp-*.mjs`。
- 历史安装包（1.0.0/1.0.1/1.0.2）从原 `release/` 迁移至 `build/installer/`。

验证：`npx vite build` 输出到 build/frontend 成功；`npm run collect` 成功收集 1.0.0~1.0.5 安装包与 1.0.4 sig。提交 `60e468b`。

## 未决：9 个 release-* 空壳目录无法立即删除

- 现象：9 个目录内 `app.asar` 同时被占用，`Directory.Delete` / `robocopy /MIR` / `cmd rd` / bash `rm -rf`（safe-delete 回收站）全部失败，错误 32。
- 诊断：文件可共享读打开、可写（已截断为 0 字节释放 256MB），但重命名与删除被拒 —— 典型安全软件以非 FILE_SHARE_DELETE 持有句柄。`Get-Process` 未发现相关本地进程；`Add-Type` 调用重启管理器 API 被安全策略拦截，未能精确定位占用进程。
- 兜底：清理脚本 `C:\Users\ybd06\temp\cleanup-newapi-builds.ps1`，重启电脑后运行即可删除；目录当前为 0 字节空壳，不影响使用。
